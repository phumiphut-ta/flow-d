1. การออกแบบ Interface สำหรับ PC Desktop เป็นหลัก (PC-First Architecture)

เนื่องจากผู้ปฏิบัติงานหลัก (Staff & Admin) นั่งทำงานหน้าจอคอมพิวเตอร์ Desktop ระบบจึงออกแบบ Layout ให้ใช้ประโยชน์จากจอแนวกว้าง (Widescreen 1080p+) ได้เต็มพื้นที่ ไม่ต้องเลื่อนจอไปมา:

  • High-Density Data Grid (ตารางความหนาแน่นสูง):
    • แสดงตารางสมุดคุมและรายการค้างในหน้าจอเดียว ปรับขนาด Row ให้กระชับ สบายตา พร้อมแถบ Sticky Header ค้างหัวตารางขณะเลื่อนดู
    • แสดงคอลัมน์สำคัญครบถ้วน: [ ] Checkbox, เลขรับ, วันที่ลงหนังสือ (พ.ศ.), Route, ขั้นตอนปัจจุบัน, เวลาที่ค้าง, ผู้ถือล่าสุด, ปุ่ม Action
  • Dual-Pane Intake & Worklist (หน้าจอแบ่ง 2 ฝั่ง สะดวกต่อการคีย์):
    • ฝั่งซ้าย (30%): ฟอร์มรับหนังสือเข้าด่วน กรอกเพียง doc_number + doc_date + เลือก Route แล้วกด Enter เพื่อบันทึกทันที
    • ฝั่งขวา (70%): ตารางหนังสือที่อยู่ระหว่างทาง (In Progress Worklist) กรองตาม Route ได้ทันที เห็นความเคลื่อนไหวอัปเดตสด
  • Keyboard Navigation & Shortcuts (ทำงานได้โดยแทบไม่ต้องจับเมาส์):
    • กด Alt + N เพื่อโฟกัสที่ช่องเลขรับหนังสือทันที
    • ในฟอร์มรับเข้า กด Enter เพื่อบันทึกรับเข้าทันที
    • กด / เพื่อโฟกัสช่องค้นหาเลขรับด่วน
  • Batch Action Toolbar: เมื่อเลือก Checkbox บนแถวตาราง แถบเครื่องมือจะแสดงปุ่มแอ็กชันขนาดใหญ่ชัดเจน: [ ติ๊กออกทั้งชุด ] และ [ ส่งต่อขั้นตอนถัดไปทั้งชุด ]

2. สถาปัตยกรรมป้องกันการกดเบิ้ล (Anti-Double Click / Idempotent System)

เพื่อตัดปัญหา Staff มือไว ดับเบิ้ลคลิกปุ่ม หรืออินเทอร์เน็ตหน่วงแล้วกดย้ำๆ จนเกิดรายการซ้ำ Flow-D ป้องกันอย่างรัดกุมทั้งฝั่ง Frontend และ Backend:

2.1 ฝั่ง Frontend UI (Immediate Button Lock & Feedback)

  • Instant Button Disabling: ทันทีที่ผู้ใช้คลิกปุ่ม (เช่น ปุ่มรับเข้า, ปุ่มติ๊กออก, ปุ่มส่งต่อ, หรือปุ่ม Batch) ปุ่มจะถูก disabled = true ทันทีใน Millisecond แรก
  • Loading Spinner & Text Feedback: เปลี่ยนข้อความปุ่มทันที เช่น จาก "ติ๊กออก" เป็น "⏳ กำลังบันทึก..." พร้อมแสดง Loading Icon เพื่อให้ผู้ใช้ทราบว่าระบบกำลังทำงาน
  • Global Form Submitting Blocker: เมื่อกด Submit ฟอร์มใดๆ เบราว์เซอร์จะบล็อกการกด Submit ซ้ำจนกว่า Request จะได้คำตอบ (HTTP Response) จาก Server กลับมา

2.2 ฝั่ง Backend Controller & Database (Atomic Lock & Idempotency)

  • Pessimistic Lock (`lockForUpdate`): เมื่อมีการติ๊กออกหรือส่งต่อขั้นตอน ระบบจะสั่ง DocumentMovement::where('id', $id)->lockForUpdate()->first() ในระดับ Database Transaction 
    DB::transaction(function () use ($movementId, $userId) {
    $movement = DocumentMovement::where('id', $movementId)->lockForUpdate()->first();
    
    // ตรวจสอบทันทีว่าถูกติ๊กออกไปแล้วหรือยัง
    if ($movement->is_returned) {
        return response()->json(['status' => 'already_processed', 'message' => 'รายการนี้ถูกดำเนินการไปแล้ว']);
    }

    $movement->update([
        'out_datetime'   => now(),
        'out_by_user_id' => $userId,
        'is_returned'    => true
    ]);
});
  • Idempotent Response: หากมี Request ที่สองหลุดเข้ามาพร้อมกันจาก Network Lag ระบบจะไม่บันทึกซ้ำ แต่จะคืนค่าสถานะสำเร็จเดิมกลับไป โดยไม่มีข้อผิดพลาดเกิดขึ้นในฐานข้อมูล

3. ข้อกำหนดทางเทคนิค: Admin Recovery (Same-day Single Undo)

กรณีเกิดข้อผิดพลาดจริงจาก Human Error (เช่น หยิบแฟ้มผิดเล่มมากด) Admin สามารถกู้คืนได้ตามเกณฑ์ 4 ข้อ:

  1. Single Step Undo Only: ย้อนได้เฉพาะ 1 ขั้นตอนล่าสุด เท่านั้น
  2. Same-day Restriction: ต้องทำรายการกู้คืน ภายในวันเดียวกัน (`DATE(action_datetime) == today()`) หากข้ามวันไปแล้ว ระบบจะล็อกสถานะถาวรเพื่อรักษายอดรายงานสมุดคุมประจำวัน
  3. Role-based Authorization: ปุ่ม Recovery จะแสดงและทำงานเฉพาะเมื่อผู้ใช้งานมีสิทธิ์ role = 'admin' เท่านั้น
  4. Audit Logging & Reason Prompt: เมื่อ Admin กดย้อนขั้นตอน ระบบจะแสดง Dialog บังคับให้ ระบุเหตุผลในการกู้คืน และบันทึกลง activity_logs ทุกครั้ง

7. Master Prompt สำหรับสั่งงาน Antigravity (Copy & Paste)

📋 Master Implementation Prompt for Antigravity AI:

Please implement the complete "Flow-D" system based on this specification file (v10):

1. PC Desktop-First UI & Anti-Double Click:
   - Primary Interface: Designed for PC widescreen monitors with high-density table view, dual-pane layout (intake on left, worklist on right), and keyboard shortcuts (Alt+N to intake, / to search, Enter to submit).
   - Anti-Double Click Protection: 
     * Frontend: Disable buttons immediately on click, show loading indicator ("กำลังบันทึก..."), and debounce form submissions.
     * Backend: Wrap checkout and step updates in DB::transaction with Pessimistic Locking (`lockForUpdate`), returning idempotent responses if already processed.

2. Document & Multi-round Business Logic:
   - Inputs: Only `doc_number` (e.g. '123/69') and `doc_date` (NO document title).
   - Re-entry Rule: If `doc_number` exists, verify that previous movement is returned (`is_returned == 1`).
     * If not returned: reject with error "รอบก่อนหน้ายังไม่ติ๊กออก ไม่สามารถเปิดรอบใหม่ได้".
     * If returned: auto-increment `round_number` and allow selecting same or different route.
   - Point-to-Point Routes: 1-click check-out setting out_datetime = now(), out_by_user_id = Auth::id(), is_returned = 1.
   - Multi-step Pipeline Routes: Advance step by step, log checkpoints to `movement_step_logs`, and mark complete at final step.

3. Admin Recovery (Same-day Single Undo - Role 'admin' only):
   - Constraint 1: Single step undo only (cannot rollback multiple steps at once).
   - Constraint 2: Must be within the SAME calendar day (action date == today). Past days are locked permanently.
   - Re-open Checked-out Document: Reset `is_returned = 0`, clear `out_datetime`, revert document status to `in_progress`.
   - Step Rollback: Decrement `current_step_index`, revert `current_step_name` to previous step, and mark latest log as 'rollbacked'.
   - Mandatory Reason Input: Prompt admin for a rollback reason and log into `activity_logs`.

4. Batch Operations:
   - Checkbox on movement tables with "Select All", allowing bulk check-out or bulk step forwarding wrapped in DB::transaction().

5. LINE LIFF Mobile Companion (/liff/tracking):
   - Mobile-first parcel-style delivery tracking UI for mobile users.
   - Search by `doc_number`.
   - Tabbed view for documents with multiple rounds: [Round 1 (Completed)], [Round 2 (Active)], defaulting to latest round.
   - Checkpoint timeline: Step name, Thai Buddhist Era datetime (d/m/Y+543 H:i), updater name, and status (completed/current/pending).

6. Authentication & Security:
   - Login with `username` and `password` only (NO email field required).
   - Support `remember` checkbox (Remember Me).
   - Self-service password change menu for users (validating current password).
   - Admin feature to directly change/reset password for any user in User Management.

7. Management, Audit Logging & Environment:
   - Windows Server IIS + FastCGI friendly (include public/web.config), PHP 8.3/8.5 compatible.
   - Dual Database: SQLite for local dev and MariaDB with fallback to config/database.production.php.
   - Device Fingerprint Middleware: Generates/reads permanent UUID cookie (`flow_device_token`), tracks client IP and device across networks.
   - Thai Buddhist Era (พ.ศ.): Eloquent Accessors converting dates to d/m/(Y+543) and datetimes to d/m/(Y+543) H:i.
